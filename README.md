# STM32 多通道环境数据采集器（IoT 上云版）

> 基于 STM32F103 的 4 通道环境数据采集器（电位器/光敏/热敏/反射式红外），通过 ESP8266 硬串口 + MQTT 上报巴法云，并自带 Web Server 实时可视化；本地 OLED 同步显示。链路：采集 → 组包 → 串口 → WiFi → 云。

## 0. 凭据配置（上传前必读）

| 项 | 说明 |
|----|------|
| WiFi 名/密码 | 代码中 `ssid` / `password` 用占位符 `"你的WiFi名"` / `"你的WiFi密码"`，真凭据不入库 |
| 巴法云 UID | 代码中 `uid` 用占位符 `"你的巴法云UID"`（巴法云后台私钥，泄露后他人可向你的主题发数据） |
| MQTT 参数 | bemfa.com:9501，clientId/用户名/密码均填 UID，Topic=esp001 |

## 1. 系统架构

```
┌────────────────┐    ADC+DMA    ┌───────────────┐   硬串口 UART0 9600   ┌──────────────┐   MQTT   ┌──────────────┐
│ 4路传感器       │ ────────────> │   STM32F103   │ ───────────────────> │   ESP8266    │ ────────> │  巴法云平台   │
│ 电位器/光敏/    │   12位/176kHz │  采集/组包    │  PA9→RX PA10→TX      │ WiFi+MQTT    │ topic=esp001 │ 网页实时可见  │
│ 热敏/红外       │               │  每秒一组     │   6行文本帧          │ +WebServer   │            │ 手机/浏览器   │
└────────────────┘               └──────┬────────┘                     └──────────────┘            └──────────────┘
                                        │ OLED 本地显示（10Hz 刷新）
                                        └──────────────────────────┘
```

## 2. 硬件清单

| 模块 | 型号/来源 | 用途 | 备注 |
|------|-----------|------|------|
| 主控 | STM32F103C8T6（江协科技开发板） | 采集/组包/上报 | GPIO/中断/PWM/ADC/DMA 已掌握 |
| WiFi 模块 | ESP8266 NodeMCU（CH340、Type-C） | WiFi + MQTT 上云 + 本地 Web | 仅支持 2.4GHz |
| 传感器 | 4 路 ADC（电位器/光敏/热敏/反射式红外） | 数据源 | PA0~PA3，AIN 模式 |
| 显示 | OLED 0.96" I2C | 本地实时显示 | 主循环 10Hz 刷新 |
| USB 转串口 | 独立 CH340 模块（调试用） | 监视 STM32 输出 | PA9 分叉，9600 |

## 3. 接线表（M3 关键接线）

| STM32 | ESP8266 | 说明 |
|-------|---------|------|
| PA9  | 板上标注 RX（UART0 RX=GPIO3） | STM32 TX → ESP8266 RX（交叉接） |
| PA10 | 板上标注 TX（UART0 TX=GPIO1） | STM32 RX ← ESP8266 TX |
| GND  | GND      | **共地（必须，否则乱码/丢帧）** |

> ⚠️ **硬串口烧录规则**：给 ESP8266 下载程序前，先拔掉 STM32 的 PA9 线（或 STM32 断电）。板上 CH340 与 STM32 共用 UART0 RX，烧录时 CH340 抢线会导致下载失败；烧完再接回。

> 调试期接法：PA9 同时分叉接「独立 CH340 模块的 RX」（串口监视器）和「ESP8266 板上 RX」——发送引脚可扇出多个接收端；PA10 只接 ESP8266 板上 TX（接收端独占，避免两个发送源打架）。

## 4. 数据帧协议（6 行组包）

- 波特率：`9600`（USART1，8N1，仅 TX）
- 上报周期：~1.24 s/组（实测组间隔 **1237ms**；`uart_task` 每轮 printf 打印 6 行（~217B @9600 ≈ 226ms）+ `vTaskDelay(1000)` 1s 节拍 + 调度开销）
- 组格式（`=====` 为组结束标志，ESP8266 据此整组转发）：

```
\r\n====== 环境数据 第12s ======\r\n
AD0=1234  电压=997mV  电位器通道\r\n
AD1=567   电压=456mV  光敏通道\r\n
AD2=890   电压=718mV  热敏通道\r\n
AD3=345   电压=278mV  反射式红外通道\r\n
===========================\r\n
```

- 通道映射：AD0=电位器、AD1=光敏、AD2=热敏、AD3=反射式红外
- 电压换算：`AD值 × 3300 / 4095`（mV）

## 6. 量化指标（实测值）

| 指标 | 数值 | 说明 |
|------|------|------|
| ADC 分辨率 | 12 位 | STM32F103 内置，4095 满量程 |
| ADC 采样率 | ~176 kHz（单通道） | ADC 时钟 12MHz（PCLK2 72MHz÷6），采样时间 55.5 周期+固定 12.5 = 68 周期 → 12M/68 ≈ 176.5k |
| 采集通道数 | 4 | 扫描模式 + DMA1 转运，一次转换取 4 路 |
| OLED 刷新率 | 10 Hz | 主循环 Delay 100ms，每次刷新 4 行数值 |
| 串口波特率 | 9600 | USART1，8N1 |
| MQTT 上报周期 | 1237 ms/组（实测） | uart_task：printf 6 行 @9600 阻塞 ≈226ms + vTaskDelay(1000) + 调度 ≈ 1237ms；改进方向见第 9 节 |
| 端到端延迟（ESP8266 收到→网页可见） | 最小 15 ms（实测） | 网页 3s 自动刷新使显示值在 0~1000ms 均匀波动（相位差），取刷新 20 次后历史最小值；串口传输 6 行约 200B @9600 ≈ 208ms（理论） |
| 代码规模 | STM32 自写 1286 行 / ESP8266 ~60 行 | 含全部驱动与 OLED 字库（main.c 149 行 + 各硬件驱动）；不含 ST 标准库与 FreeRTOS 内核；ESP8266 以实际 .ino 为准 |
| 运行形态 | **FreeRTOS 9.0.0 多任务版（主版本）** | 5 任务：采集(3)/显示(2)/串口(2)/按键(4)/LED(1)，抢占式调度 + 时间片；裸机版另存备份 |

## 7. 遇到的问题与解决（排障记录，面试证据）

1. **Arduino 板载库下载超时**：官方 GitHub 源被墙 → 改用 DFRobot 镜像 `https://download.dfrobot.top/package_esp8266com_index.json`，正常安装 esp8266 3.1.2。
2. **WiFi 连接无 OK 返回**：家庭路由为授权登录模式，非开放 WiFi → 确认联网成功后继续执行，最终 `WiFi OK, IP: 192.168.x.x`。
3. **串口乱码（可辨别内容）**：STM32 打印含中文标签（Keil 按 GBK 编码发出），巴法云网页按 UTF-8 解析导致中文乱码 → 改为纯 ASCII 帧格式解决。
4. **波特率不一致乱码**：STM32=9600、ESP8266=115200 → 统一 9600（UART0 同一串口，接收波特率与监视器波特率必须一致）。
5. **面包板放不下 ESP8266**：改用母对母杜邦线直连排针，模块悬空放置，RX/TX/GND 三线引出。
6. **网页只显示最后一行**：改为组缓冲——收行累积到 `buffer`，检测到 `=====` 组结束标志后整组交付网页并 publish。
7. **硬串口烧录失败风险**：CH340 与 STM32 抢 UART0 RX → 烧录前拔 STM32 PA9 线。
